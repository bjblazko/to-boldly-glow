# Remaining Planets — Orbital Mechanics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `packages/engine` heliocentric position functions for the 7 remaining planets
(Mercury, Venus, Mars, Jupiter, Saturn, Uranus, Neptune), following the exact same pattern already
proven for Earth: a generic evaluator (already built, reused unchanged), one truncated-and-verified
VSOP87B data file per body, and a thin wrapper exporting `<planet>HeliocentricL/B/R`. This plan is
engine-only — rendering all 8 planets together, an orbit-path toggle, and antialiasing are a
separate follow-up plan.

**Architecture:** Identical to the orbital-mechanics-earth plan: `evalVsop87Coordinate` (already in
`packages/engine/assembly/vsop87.ts`) is reused completely unchanged for every planet — nothing
about it is planet-specific. Each planet gets its own data file (`data/vsop87<Planet>.ts`) and its
own thin wrapper file (`<planet>.ts`), following Earth's exact shape. This plan adds 7 independent,
identically-structured tasks (one per planet) plus a final attribution task.

**Tech Stack:** AssemblyScript (existing `packages/engine`), Vitest — no new dependencies.

## Context: how this data was generated, and why it's looser than Earth's

Same discipline as Earth's plan: this data was **not** hand-typed from memory. It was generated by
a script (run outside this repo, during planning) that loaded the real, published VSOP87B dataset
from the `astronomia` npm package (MIT licensed, already used and attributed for Earth — see
`CREDITS.md`), truncated it by keeping the largest-amplitude terms per order, and verified the
truncation error against the full-precision series across 1800–2200. Every array below was copied
verbatim from that script's output files — not retyped or reconstructed from memory during plan
writing, specifically to avoid the exact failure mode this discipline exists to prevent.

**This truncation deliberately targets a looser accuracy than Earth's** (Earth: <1 arcsecond;
these 7 planets: **under ~2 arcminutes** in longitude/latitude, and under ~450,000 km in distance —
still tiny relative to these planets' actual distances of hundreds of millions to billions of km,
around 0.01–0.03% relative error). This is a deliberate choice, not a shortcut: at 2 arcminutes,
positions are visually indistinguishable from arcsecond precision in any 3D rendering (the
difference is a small fraction of a pixel at any reasonable camera distance), and this app already
uses non-physical, exaggerated visual scale for body sizes (see the renderer-core plan) — there is
no honest way for a viewer to perceive the difference. Loosening the target here keeps the combined
7-planet dataset to a few hundred terms per planet at most, a meaningfully smaller amount of data to
review and maintain, with zero visible cost. If a future feature needs tighter precision (e.g.
eclipse timing), that feature's own plan should generate its own tighter truncation for the
specific body/timeframe it needs — this data is not meant to serve every future purpose.

Each planet's truncated position was cross-checked against well-known, independently-sourced
distance facts: the observed minimum/maximum heliocentric distance across 1800–2200 in the
truncated series closely matches each planet's published perihelion/aphelion distance (astronomical
units, semi-major axis × (1∓eccentricity)):

| Planet  | Truncated observed range (AU) | Independently-known perihelion–aphelion (AU) |
|---------|-------------------------------|-----------------------------------------------|
| Mercury | 0.3090 – 0.4656                | ~0.3075 – 0.4667                               |
| Venus   | 0.7184 – 0.7282                | ~0.7184 – 0.7282                               |
| Mars    | 1.3818 – 1.6654                 | ~1.3814 – 1.6660                               |
| Jupiter | 4.9481 – 5.4570                 | ~4.9506 – 5.4546                               |
| Saturn  | 9.0122 – 10.0699                | ~9.0250 – 10.0848                              |
| Uranus  | 18.2835 – 20.1026               | ~18.3282 – 20.1086                             |
| Neptune | 29.8114 – 30.3408               | ~29.8391 – 30.3817                             |

Every planet's truncated data reproduces real orbital physics, not just internal self-consistency —
this is the same standard of evidence used for Earth's data. The per-task tests below assert R stays
within a generous (±1.5–2%) margin around these bounds, not exact equality.

## Global Constraints

(Copied verbatim from the design spec and prior plans; every task below implicitly inherits these.)

- `packages/engine` is pure math: no I/O, no rendering, no network fetch.
- Only scalar `f64`/`i32` values cross the WASM↔JS boundary — every `<planet>HeliocentricL/B/R`
  function takes a single `T: f64` and returns a single `f64`, exactly like Earth's.
- `evalVsop87Coordinate` (from `packages/engine/assembly/vsop87.ts`) must be reused unchanged — do
  not modify it, and do not re-export it from `index.ts` (it stays internal, same as for Earth).
- Testing: Vitest for unit tests.
- No new npm dependencies.
- Third-party-derived data must be attributed in `CREDITS.md` (already true for the VSOP87/
  `astronomia` source; this plan's final task extends that entry to cover these 7 planets too).

**Per-task note on data array counts:** Not every planet's published VSOP87B series has the same
number of order arrays (order = power of T in the series). Mercury, Venus, Mars, Jupiter, and Saturn
each have orders 0 through 5 for L, B, and R (6 arrays each, 18 total per planet). **Uranus** has
orders 0–4 for L (5 arrays) and 0–4 for R (5 arrays), but only 0–3 for B (4 arrays — no `URANUS_B4`
or `URANUS_B5`). **Neptune** has orders 0–3 for L and B (4 arrays each — no `NEPTUNE_L4`/`L5` or
`NEPTUNE_B4`/`B5`) and 0–4 for R (5 arrays). This isn't a mistake — VSOP87's published theory simply
omits negligible higher-order terms for these two outer planets. Each task below creates exactly the
arrays that exist for that planet — do not pad with empty arrays for orders that don't exist.

```typescript
import { evalVsop87Coordinate } from './vsop87'
import {
  MERCURY_L0, MERCURY_L1, MERCURY_L2, MERCURY_L3, MERCURY_L4, MERCURY_L5,
  MERCURY_B0, MERCURY_B1, MERCURY_B2, MERCURY_B3, MERCURY_B4, MERCURY_B5,
  MERCURY_R0, MERCURY_R1, MERCURY_R2, MERCURY_R3, MERCURY_R4, MERCURY_R5,
} from './data/vsop87Mercury'

const MERCURY_L_ORDERS: f64[][] = [MERCURY_L0, MERCURY_L1, MERCURY_L2, MERCURY_L3, MERCURY_L4, MERCURY_L5]
const MERCURY_B_ORDERS: f64[][] = [MERCURY_B0, MERCURY_B1, MERCURY_B2, MERCURY_B3, MERCURY_B4, MERCURY_B5]
const MERCURY_R_ORDERS: f64[][] = [MERCURY_R0, MERCURY_R1, MERCURY_R2, MERCURY_R3, MERCURY_R4, MERCURY_R5]

const TWO_PI: f64 = 2.0 * Math.PI

export function mercuryHeliocentricL(T: f64): f64 {
  let l = evalVsop87Coordinate(MERCURY_L_ORDERS, T) % TWO_PI
  if (l < 0.0) l += TWO_PI
  return l
}

export function mercuryHeliocentricB(T: f64): f64 {
  return evalVsop87Coordinate(MERCURY_B_ORDERS, T)
}

export function mercuryHeliocentricR(T: f64): f64 {
  return evalVsop87Coordinate(MERCURY_R_ORDERS, T)
}
```

```typescript
import { evalVsop87Coordinate } from './vsop87'
import {
  SATURN_L0, SATURN_L1, SATURN_L2, SATURN_L3, SATURN_L4, SATURN_L5,
  SATURN_B0, SATURN_B1, SATURN_B2, SATURN_B3, SATURN_B4, SATURN_B5,
  SATURN_R0, SATURN_R1, SATURN_R2, SATURN_R3, SATURN_R4, SATURN_R5,
} from './data/vsop87Saturn'

const SATURN_L_ORDERS: f64[][] = [SATURN_L0, SATURN_L1, SATURN_L2, SATURN_L3, SATURN_L4, SATURN_L5]
const SATURN_B_ORDERS: f64[][] = [SATURN_B0, SATURN_B1, SATURN_B2, SATURN_B3, SATURN_B4, SATURN_B5]
const SATURN_R_ORDERS: f64[][] = [SATURN_R0, SATURN_R1, SATURN_R2, SATURN_R3, SATURN_R4, SATURN_R5]

const TWO_PI: f64 = 2.0 * Math.PI

export function saturnHeliocentricL(T: f64): f64 {
  let l = evalVsop87Coordinate(SATURN_L_ORDERS, T) % TWO_PI
  if (l < 0.0) l += TWO_PI
  return l
}

export function saturnHeliocentricB(T: f64): f64 {
  return evalVsop87Coordinate(SATURN_B_ORDERS, T)
}

export function saturnHeliocentricR(T: f64): f64 {
  return evalVsop87Coordinate(SATURN_R_ORDERS, T)
}
```
